# Этап 2. Выбор технологий искусственного интеллекта

## Задача с точки зрения ИИ

- **Определение отдела** — многоклассовая классификация коротких текстов на
  русском языке (8 классов).
- **Определение срочности** — бинарная задача; признаки срочности явные
  («срочно», «завтра», «дедлайн», «отчисляют»).

## Сравнение подходов

| Критерий | Правила по ключевым словам | **TF-IDF + логистическая регрессия** | Дообучение ruBERT | LLM через API (GPT/Claude/GigaChat) |
|---|---|---|---|---|
| Точность на типовых обращениях | Средняя, падает на новых формулировках | Высокая | Очень высокая | Высокая без обучения |
| Требования к железу | Нет | Обычный ПК, CPU | GPU для обучения | Нет (внешний сервис) |
| Стоимость эксплуатации | ≈ 0 | ≈ 0 | Сервер с GPU | Плата за каждый запрос |
| Скорость ответа | Мгновенно | Миллисекунды | Десятки миллисекунд | Секунды |
| Объяснимость | Полная | Хорошая (веса слов) | Слабая | Слабая |
| Объём данных для обучения | Не нужен | Сотни–тысячи примеров | Тысячи примеров | Не нужен |
| Персональные данные (152-ФЗ) | Внутри вуза | Внутри вуза | Внутри вуза | Данные уходят внешнему провайдеру |
| Сопровождение | Ручное обновление словарей | Переобучение за секунды | Нужен ML-инженер | Зависимость от провайдера |

## Решение

1. **Отдел — TF-IDF + логистическая регрессия** (scikit-learn):
   - два набора признаков: словесные n-граммы (1–2 слова) передают смысл,
     символьные n-граммы (3–5 символов) делают модель устойчивой к опечаткам и
     разным формам слов без морфологического анализатора;
   - модель выдаёт **вероятность** для каждого отдела — это используется как
     «уверенность» и позволяет отправлять сомнительные случаи человеку;
   - обучается за секунды на обычном компьютере, поэтому дообучение на
     исправлениях операторов можно запускать прямо из интерфейса;
   - данные студентов не покидают инфраструктуру университета.
2. **Срочность — правила по ключевым словам.** Признаки срочности немногочисленны
   и явные; правила проще проверить и объяснить, чем отдельную модель.
3. **Порог уверенности 60 %.** Ниже порога обращение идёт в очередь оператора.
   Порог — компромисс между долей автоматизации и риском ошибок; его можно
   менять в `router/config.py`.
4. **Правило нескольких вопросов.** Обращение тоже идёт оператору, если:
   - второй по вероятности отдел набрал 12 % и больше;
   - или в тексте есть маркер второго вопроса («и ещё», «также», «кроме того»,
     «ещё вопрос», два и больше «?»), а второй отдел набрал хотя бы 5 %.

   Правило добавлено после анализа первой версии и ручной проверки. На имитации оно
   сократило число ошибок без проверки человеком с 12 до 0 (см. `docs/results.md`).
   Пороги `SECOND_OPTION_THRESHOLD` и `MARKER_SECOND_OPTION_THRESHOLD` и список
   маркеров (`router/multi_topic.py`) настраиваются.

## Путь развития

- При накоплении нескольких тысяч реальных обращений — сравнить текущую модель с
  дообученной ruBERT и перейти на неё, если прирост точности оправдывает затраты на GPU.
- Для обращений с несколькими вопросами — перейти на multi-label классификацию
  (несколько отделов на одно обращение).
- Для срочности — обучить отдельный классификатор на размеченных операторами примерах.
